## 三篇文章的可发布结构

### 1. 从现有客户端迁移 `mcpServers` JSON

- **承诺边界**：把受信 HTTP/stdio MCP Server 配置迁入统一管理；不把普通 API/CLI 自动转成 MCP Server。
- **最小步骤**：脱敏备份 → 导入一条连接 → 确认范围 → 找到预期工具 → Host 审批后只读调用。
- **必保留的警示**：`stdio` 不等于数据不出本机；上游服务可能计费；凭据只在本机填写。
- **成功判据**：配置、发现/注册、业务调用三层独立通过。

### 2. OAuth 从未连接到首次只读调用

- **承诺边界**：插件支持 OAuth 2.0 PKCE 流程；是否开放取决于服务商客户端注册、账号、组织和 scope 政策。
- **最小步骤**：确认套餐/管理员/scope → 单次授权 → 检查诊断 → 确认工具 → Host 审批后只读调用。
- **必保留的警示**：客户端注册 403 不是用户登录失败；回调在本机不代表数据仅留在本机。
- **成功判据**：授权、工具注册、业务调用三层独立通过。

### 3. 连接异常时找到工具并恢复发现

- **承诺边界**：搜索本地安全缓存不执行目标工具；“检查连接/重新发现”会联系 MCP Server。
- **最小步骤**：确认 Workspace/范围 → 搜索和筛选 → 核对 Schema → 记录稳定 code → 只做一个建议动作 → 只读调用验收。
- **必保留的警示**：旧缓存可见不等于当前可调用；不连续点击绕过限流；检查/发现请求可能计入配额。
- **成功判据**：连接、发现/注册、业务调用三层独立通过。
